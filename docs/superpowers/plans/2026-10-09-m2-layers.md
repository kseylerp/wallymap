# WildMap Milestone 2: Data Layers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the wild-first data layers (fire, forest loss, snow, water, camping, public land, species, photos, population, night lights, regions) plus the two computed scores (popularity, remoteness), a vocabulary that routes questions to layers, and the layer-stack and inspect UI, so questions like "wildfire in the last 10 years near Tahoe" or "where is the least-touched land in Montana" get real answers.

**Architecture:** Every dataset is one file in `layers/` conforming to the existing `Layer` contract (`layers/types.ts`), registered in `layers/index.ts`, and automatically exposed as an agent tool and `/api/layer/[id]` route. Shared upstream helpers live in `layers/_shared/` (Overpass, ArcGIS FeatureServer, NASA GIBS tiles). Features carry `t` (ISO date) and `v` (number) where the data has them; the renderer uses them in Milestone 3. Vector tiles join raster tiles as a second `tiles` format. Computed scores compose other layers' queries.

**Tech Stack:** as Milestone 1 (Next.js 16, zod v4, vitest, Vercel AI SDK v7). New: `h3-js` for the remoteness grid, `papaparse`-free CSV parsing (hand-rolled, FIRMS CSV is simple).

**Spec:** `docs/superpowers/specs/2026-10-09-mapagent-design.md` (sections "The layer registry", "Launch layers", "Popularity estimate", "Remoteness score") and `docs/superpowers/specs/2026-10-09-wildmap-restyle.md` (visual tokens). Priority ruling: wild/natural first; cell coverage and Foursquare places are cut from this milestone.

## Global Constraints

- TypeScript strict; no `any` in `layers/` or `lib/`.
- Every layer: unique `id`, `title`, one-paragraph `description` written for the model (what it is, units, caveats, when to use), `coverage` (`"global" | "us" | { bbox }`), `license` string, `requiredEnv` / `optionalEnv`, `maxAreaKm2`, zod `input`, `style`, and a fixture test that runs with no keys.
- Feature properties: `t` is an ISO 8601 string, `v` is a number; both optional; nothing else uses those names.
- Layers read env only through `ctx.env`; upstream calls go through `ctx.fetch` with `cacheKey: ctx.cacheKey` (append a suffix when a layer makes several requests).
- Timeouts: every upstream request carries `signal: AbortSignal.timeout(25_000)`.
- Area limits: polygons/tiles layers may allow large areas (tiles: `maxAreaKm2: 50_000_000`); point/line layers choose a limit that keeps responses under ~2 MB.
- No scraping of sites that forbid it. No new static data files except `data/nps-visitation.csv` if Task 15 uses it (≤ 2 MB).
- Every commit message ends with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- `pnpm test`, `pnpm typecheck`, `pnpm lint` (0 warnings), `pnpm build` pass after every task.

## Review Focus

1. An ArcGIS FeatureServer that returns `{ "error": {...} }` with HTTP 200 must become `{ hint: "upstream" }`, never an empty "no fires here". Pinned in Task 1.
2. A FIRMS request without `FIRMS_MAP_KEY` must be reported by `list_layers` as unavailable and by `runLayer` as 503, never reach NASA. Pinned in Task 3 (existing `runLayer` behavior; test asserts the layer declares the env).
3. Vector tiles (`format: "vector"`) must render through Mapbox's own source, not deck.gl, and must survive a basemap swap. Pinned in Task 7.
4. Popularity and remoteness must never be described as live, and the inspect card must show their contributing signals. Pinned in Tasks 15, 16, 18.
5. A layer whose upstream is slow must not stall the whole chat turn past Vercel's limit: per-request 25 s timeouts and the agent's 8-step cap. Pinned in Task 0 (shared helpers carry the timeout).
