# M4: wild-data batch (drill-down, over time, 3D, heat, activity modes)

Owner ask (2026-10-09, late): "do a mix of all that. really emphasize data that can be drilled down, seen over time, has a 3D element to it, can show something interesting with a heatmap or mode of transportation like mtb, trail, climbing, ski, etc." Source menu: `docs/superpowers/specs/2026-10-09-dataset-menu.md`.

Contract: one file per layer under `layers/`, `defineLayer`, registered in `layers/index.ts`, bbox-bounded with `maxAreaKm2`, `requiredEnv`/`optionalEnv`, `license` + citation, feature props `t` (ISO date) and `v` (number) where they exist, `kind` for category filters, cached fetch via `ctx.fetch` with `ctx.cacheKey`, shared helpers in `layers/_shared/` (overpass, arcgis, gibs, coverage, geo). Keyless sources only in this batch. Every layer: unit test with a recorded fixture, a live smoke check noted in the file header, a one-paragraph `description` written for the model (what, unit, caveats, example questions), synonyms for vocabulary routing.

## Task 0: contract additions (first; small)
- `StyleHints` gains optional `extrude?: "v" | "count"` (3D columns), `heat?: boolean` (heatmap mode makes sense), `cluster?: boolean` (dense points), `timeField?: string` (defaults to `t`).
- Tile results gain `data.time?: { template: string (with `{date}` or `{year}`), cadence: "daily" | "8day" | "16day" | "monthly" | "yearly", from: string, to?: string, daysBack?: number }` so the scrubber can rewrite any time-tile URL generically; `lib/time/index.ts` uses it and `night-lights` + `forest-loss` migrate to it (no behaviour change).
